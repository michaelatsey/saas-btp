# SQL / DDL Conventions

Applies to every DbUp migration script (ADR-ARCH-006). Domain identifier rules live in
naming.md; this file covers the database schema surface only.

## Casing & naming
- snake_case for all schemas, tables, columns, constraints, indexes.
- Tables: plural (`constats`). Schemas: bounded-context name (`safety`, `access`, `site`).
- One schema per bounded context, created just-in-time with its first table
  (`CREATE SCHEMA IF NOT EXISTS <context>;` at the top of that context's first script).
  No pre-created empty schemas.

## Keys
- Primary key column `id`: `uuid`, UUIDv7, generated by the aggregate creator (see naming.md).
- Foreign keys: `<referenced_singular>_id` (`site_id`, `tenant_id`).
- No surrogate integer keys.

## Constraint & index naming
- `pk_<table>`                 primary key
- `fk_<table>__<ref_table>`    foreign key
- `ck_<table>__<rule>`         check
- `ux_<table>__<cols>`         unique
- `ix_<table>__<cols>`         non-unique index

## Types
- Timestamps: `timestamptz`, stored UTC. No naked `timestamp`.
- Business time and system time are distinct columns (`occurred_at` vs `created_at`).
- Strings: `varchar(n)` with an explicit, justified length; `text` only for truly unbounded content.
- Numbers with meaning: `numeric` with explicit precision, never `float`.

## Closed sets (enums)
- Stored as `varchar` + a `CHECK` listing allowed tokens. Not a PostgreSQL `ENUM` type
  (rigid to alter, couples Npgsql to a registered type); not an integer (opaque in DB,
  reporting, PowerSync payloads).
- Tokens are lowercase snake_case technical English, decoupled from the C# identifier and
  from any UI label (localization stays in domain/UI). E.g. `critical`, `dangerous_situation`.
- The Domain Value Object is the source of truth for validity; the `CHECK` is defense-in-depth.
- Mapping is an explicit EF value converter (VO <-> token). Never rely on an implicit
  `Enum.ToString()`, so a C# rename can never silently drift from the stored token.

## Nullability
- `NOT NULL` by default; every nullable column is explicit and justified.

## Audit / lifecycle
- `created_at timestamptz NOT NULL` (server-stamped) on every table.
- `updated_at` / `deleted_at` / `version` are NOT added by default. They appear only when a
  real behavior requires them. Insert-only aggregates carry none.

## Optimistic concurrency
- Mutable aggregates: PostgreSQL `xmin` as the concurrency token via EF
  (`UseXminAsConcurrencyToken`) — no dedicated DDL column.
- Insert-only aggregates: no concurrency mechanism.
- Applied at the EF mapping of the first mutable aggregate; documented here so no `version`
  column is ever added speculatively. (Exact Npgsql API confirmed at EF wiring.)

## RLS
- RLS enabled on every business table; tenant-isolation policy keyed on `tenant_id`.
- The .NET domain is the write authority (ADR-ARCH-005) and connects with a privileged role
  that bypasses RLS; RLS is defense-in-depth for any other access path.
