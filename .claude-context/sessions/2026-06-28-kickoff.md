## Décisions actées

### Cap (north star) — AI OS ✅
- Cible AI OS conservée intégralement (15 agents, double finalité produit + expertise vendable).
- Méthode : progressive, jamais big-bang ; chaque agent/connexion naît d'un besoin réel ;
  une seule connexion à la fois ; n8n seulement sur un handoff fait 5 fois à la main.
- Enregistré dans `context/ai-os/ai-os-vision.md` + roadmap 6 paliers dans `ai-os-roadmap.md`.

### Structure projet ✅
- Calquée sur la convention MicroKit (`.claude-context/sessions/` + `context/`).
- Deux pôles distincts : `context/product/` et `context/ai-os/`.
- ADRs à 3 préfixes : `ADR-PROD` / `ADR-ARCH` / `ADR-ORG`.
- `CLAUDE.md` à la RACINE (convention Claude Code officielle vérifiée : auto-load +
  survit à la compaction). Pas dans `.claude/`.

### Mono-repo ✅
- Décision : mono-repo unique pour le SaaS BTP (`~/workspace/products/saas-btp/`).
- Rationale : contexte unifié pour les agents, PR atomiques cross-app, réutilisation de
  la discipline MicroKit.
- 3 garde-fous actés : CI à path-filters par app, pipelines de deploy séparés par app,
  `.gitignore` strict multi-toolchain.

### ADR-ARCH-001 — frontière de contrat OpenAPI ✅
- Décision : les types TS sont générés depuis le document OpenAPI, PAS depuis le C#.
- .NET 10 génère l'OpenAPI nativement (Swashbuckle retiré), build-time + committé.
- OpenAPI 3.1 / JSON Schema 2020-12 : génération TS sans bug sur modèles complexes.
- `apps/api` reste isolée du workspace pnpm. Générateur (Kiota/openapi-typescript/...) : JIT.
