## Completed

### 3.1 — Slice 1 decomposed into 8 vertical stories

Vertical slices (each cuts through the full stack, independently demonstrable):

1. spike: PowerSync Web offline + photo capture on target Android (gates ADR-ARCH-003)
2. Access: authenticate + scope user to tenant/site (foundational)
3. Safety: capture a constat offline with a photo
4. CorrectiveActions: create a corrective action from a constat (user-initiated)
5. CorrectiveActions: assign + schedule (owner, deadline, priority)
6. CorrectiveActions: process -> validate -> close
7. Notifications: notify on due date + critical severity
8. CorrectiveActions: operational dashboard (read-model)

Design decisions taken during decomposition:
- No separate "sync" story. Device <-> Postgres sync is infra (PowerSync, configured
  once, validated by the spike) + the `offline` label on affected stories — not a
  product story. Avoids a horizontal (layer) slice.
- No separate "display/read" story. List/detail views are included in the story that
  needs them (can't assign/close what you can't see).
- Corrective-action creation is USER-INITIATED, not automatic on every constat.
  Auto-creating a ticket per constat = operational noise, contradicts the opinionated-
  but-not-blind-automation product stance. The user promotes a constat (forced if
  severity critical). Still exercises the outbox/inbox event pattern.
- Dashboard placed TEMPORARILY under CorrectiveActions for increment 1 (no
  ctx:reporting label; Reporting not opened yet — architecture.md 7). Migration to a
  Reporting context noted for later (future ADR).
- Comments on corrective actions: out of scope for slice 1 (light add later if needed).

## Incidents / lessons

| Incident | Lesson |
|----------|--------|
| `gh issue create --project "SaaS BTP"` failed: "error fetching repo projects (classic)". | Known gh bug: `--project` on issue/pr create/edit resolves Projects *classic* (deprecated) and fails against a Project v2. Do NOT use `--project` at creation for v2 boards. |
| Fix | Two-step: `gh issue create` (no --project), capture the URL, then `gh project item-add 9 --owner michaelatsey --url "$url"`. Item lands in Backlog (board default). |
| Verified nothing was created before retry (`gh issue list --state all` = empty) to avoid duplicates. | An error during metadata resolution aborts before creation — but always verify state before re-running a batch. |
